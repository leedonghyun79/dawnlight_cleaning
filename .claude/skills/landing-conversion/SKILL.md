# 랜딩페이지 전환율 기준

## 1. 공통 뼈대 (모든 업종)

훅 → 공감/필요 → 해결책 → 증거 → 불안 제거 → 행동(CTA)

방문자 심리 순서: "이게 뭐지 → 나한테 필요한가 → 믿어도 되나 → 손해 볼 건 없나 → 지금 해볼까"

흐름은 고정하고, 각 단계에 들어가는 섹션만 업종에 따라 바꾼다.

## 2. 업종 모듈 고르기

업종에 맞는 모듈을 `references/`에서 읽고 출발점으로 삼는다.

| 업종 | 파일 |
|------|------|
| 지역 서비스 (청소, 인테리어, 이사, 방역, 수리) | `references/local-service.md` |
| SaaS / 앱 | `references/saas.md` |
| 쇼핑몰 메인 | `references/shop.md` |
| B2B / 외주 / 에이전시 | `references/b2b-agency.md` |
| 교육 / 강의 / 코칭 | `references/education.md` |
| 병원 / 뷰티 / 의료 | `references/medical.md` (법적 주의 필수) |
| 오프라인 매장 / 음식점 / 공간 대여 | `references/store.md` |

해당 업종이 없으면 가장 가까운 모듈을 조합하고, 어떤 모듈을 기준으로 했는지 답변에 명시한다.

## 3. 정보 확인 (작업 전)

아래 정보가 없으면 가정을 명시하고 진행한다. 핵심 정보(업종, 전환 목표)가 전혀 없을 때만 먼저 묻는다.

- 업종과 서비스 내용
- 페이지 유형: 랜딩페이지(광고 유입, 목표 1개) / 랜딩형 메인페이지(다목적 방문자)
- 핵심 전환 목표: 전화, 카톡, 폼 문의, 회원가입, 구매, 예약 중 무엇인가
- 핵심 타겟
- 보유 증거 데이터: 시공/판매 건수, 후기, 평점, 비포애프터, 수상, 언론, 파트너사
- 보증/정책: 환불, 재작업, 보험, 무료체험 여부

## 4. 페이지 유형별 규칙

- **랜딩페이지**: 내비게이션 제거, CTA 목표 1개, 모든 섹션이 하나의 전환으로 수렴한다.
- **랜딩형 메인페이지**: 헤더 메뉴를 유지한다. 상세(전체 후기, 전체 사례)는 하위 페이지로 분리하고 메인에는 요약만 둔다. **헤더 메뉴의 모든 항목은 메인에 요약 섹션이라도 반드시 있어야 한다.**

## 5. 공통 원칙

- 방문자는 **3초 안에** 이탈 여부를 결정한다. 헤드라인에서 핵심 혜택이 5초 안에 읽혀야 한다.
- 모바일 트래픽이 60% 이상이면 모바일 우선으로 설계한다.
- CTA는 Above the fold, 스크롤 중간 3~4회 반복, 하단 최종 위치에 둔다. 버튼 최소 44×44px.
- 기능이 아니라 **고객이 얻는 결과**로 쓴다. 예: ❌ "24/7 지원" → ✅ "밤새 걱정 없이 주무세요".
- 헤드라인, USP 요청에는 3~5개 버전을 준다.

## 6. 신뢰와 불안 제거

- 후기: 구체적 수치가 있는 것을 우선한다. 이름(이니셜), 지역, 평수, 사진이 함께 있으면 신뢰가 높아진다.
- 수치: 구체적인 숫자가 신뢰를 만든다. "많은 고객" 대신 실제 건수.
- 보증: 고객의 리스크를 제거하면 전환이 쉬워진다. 단, 실제 약관과 일치해야 한다.
- 인증·권위: 수상, 언론, 인증 마크, 파트너사 로고.
- 긴박감(FOMO): 진실한 긴박감만 쓴다. 가짜 카운트다운, 가짜 마감은 금지.
- 필수 안심 요소: 개인정보 처리 안내, 고객 지원 연락처, FAQ, 숨겨진 비용 없음(사실일 때만), 해지·취소 방법.

## 7. CTA 문구

- 동사로 시작한다: ❌ "제출" → ✅ "지금 시작하기"
- 혜택을 명시한다: ❌ "클릭하기" → ✅ "무료로 견적 받기"
- 버튼 아래 안심 문구를 둔다. 단, 실제 정책일 때만 쓴다.

## 8. 데이터 원칙 (반드시 지킨다)

- 수치, 후기, 수상 이력, 보증 정책은 **사용자가 제공한 것만** 쓴다. 지어내지 않는다.
- 예시 문구의 숫자(47%, 37%, 12,847명 등)는 형식 예시일 뿐이다. 실제 사이트에 그대로 쓰지 않는다.
- 자료가 없으면 `[누적 시공 건수]`, `[고객 후기 3건]` 같은 자리표시자로 남긴다.
- 실제 공개 페이지에서는 자리표시자를 노출하지 않는다. "준비 중" 틀로 두거나 섹션을 숨긴다.
- 답변 끝에 **채워야 할 데이터 목록**을 모아서 정리한다.

## 9. 출력 형식

구조 설계 요청일 때만 아래 형식으로 답한다. 카피 한 줄 수정 같은 작은 요청에는 적용하지 않는다.

1. 적용 모듈과 가정한 정보
2. 섹션 순서표: 섹션명 / 목적 / 들어갈 요소 / 우선순위(필수·권장·선택)
3. 섹션별 카피 초안 (헤드라인은 3~5개 버전)
4. CTA 배치 위치와 문구
5. 해당 업종에서 빠지면 안 되는 신뢰·불안 제거 요소
6. 첫 A/B 테스트 추천 1~2개 (변수 하나씩)
7. 채워야 할 데이터 목록

리뷰 요청이면 위 체크리스트 기준으로 항목별 피드백을 준다.

## 10. 론칭 전 점검

- [ ] 헤드라인에서 핵심 혜택이 5초 안에 전달되는가
- [ ] 타겟이 명확한가
- [ ] 혜택 중심 문구인가
- [ ] CTA가 구체적이고 행동을 부르는가
- [ ] 실제 후기가 있는가 (이름, 지역 등 동의받은 정보)
- [ ] 구체적인 실제 수치가 있는가
- [ ] 환불·보증 정책이 명확하고 실제와 일치하는가
- [ ] 모바일에서 CTA와 레이아웃이 정상인가
- [ ] 헤더 메뉴 항목이 모두 메인에 요약되어 있는가
- [ ] 자리표시자가 공개 화면에 노출되지 않는가
- [ ] 추적 코드(GA4 등)와 A/B 테스트 계획이 있는가

## 11. 이 프로젝트 (todays-clean)

- 업종: 청소업체 → `references/local-service.md` 기준
- 홈 구성은 `src/app/page.tsx` 순서가 기준이다. 섹션을 바꾸면 이 파일의 설명과 함께 맞춘다.
- 개인정보를 받기 전에 개인정보처리방침 페이지를 먼저 만든다. 현재 푸터 링크는 아직 `#`이다.
- 카카오톡 채널 주소(`company.ts`의 `kakaoChannelUrl`)가 비어 있으면 카톡 버튼은 숨겨진다.
